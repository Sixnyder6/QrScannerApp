# Документация по модулю Storage (Склад/Хранение)

Этот документ описывает структуру и назначение файлов, относящихся к функционалу управления хранением (ячейками склада) внутри модуля `inventory`.

---

### 📂 `features/inventory/ui/storage` (UI Слой)
Модуль Storage отвечает за управление физическим или логическим хранением (ячейками склада). Экран построен на современном стеке Jetpack Compose с использованием архитектуры MVVM, реактивного управления состояниями (StateFlow) и сложного UI с множеством модальных окон (Bottom Sheets, Dialogs).
🎨 1. Визуальный стиль и Дизайн-система (Stardust Theme)
Интерфейс использует кастомную дизайн-систему Stardust, которая опирается на «Glassmorphism» (эффект матового стекла), градиенты и скругленные формы.
Цветовая палитра:
Используются фирменные цвета: StardustPrimary (основной акцент), StardustSecondary, StardustSuccess (зеленый для успешных действий/свободного места), StardustError (красный для удалений/заполненности).
Фоны элементов (StardustGlassBg, StardustItemBg) полупрозрачные, что создает ощущение глубины.
Градиенты: Карточки ячеек (StorageCellTile) динамически меняют градиент фона от полупрозрачного к красному в зависимости от процента заполненности.
Типографика: Иерархия выстроена через размеры (headlineLarge для заголовков, 10.sp для метаданных) и насыщенность (FontWeight.ExtraBold, SemiBold).
Terminal Style: Выделенный визуальный стиль для истории операций внутри ячейки (CellOperationsTerminal). Использует моноширинный шрифт (FontFamily.Monospace) и хакерскую цветовую схему (чёрный фон TerminalBg, зелёный текст TerminalGreen, красные/желтые акценты).
🎬 2. Анимации и Микроинтеракции
Модуль насыщен плавными анимациями, улучшающими UX и дающими четкий отклик на действия пользователя.
Переходы состояний (Crossfade): Плавная смена верхней панели (TopAppBar) при переходе в режим выделения (Selection Mode) и обратно. Плавное переключение вкладок «Список/Терминал».
Физика пружины (Spring Physics):
Анимация масштабирования карточки при долгом нажатии (tileScale через spring(dampingRatio = MediumBouncy)).
Появление галочки выбора ячейки (отскок размера checkScale).
Анимация прогресс-бара: Заполнение полоски емкости ячейки происходит плавно (tween(600)).
Анимации списков:
Постепенное появление карточек сетки при загрузке (задержка delayMillis = index * 40).
Плавное появление строк в терминале истории (tween(200, LinearEasing)).
Анимации видимости (AnimatedVisibility):
Появление кнопки «Создать» (выплывает снизу scaleIn).
Появление/исчезновение баннера «В буфере» (expandVertically + fadeIn).
Раскрытие/сворачивание описания ячейки с вращением иконки-стрелочки (animateFloatAsState 0f -> 180f).
Динамические цвета: Плавная смена цвета чипсов фильтров и обводки карточек (animateColorAsState с длительностью 200-300мс).
🛡️ 3. Защита от дурака (Foolproof mechanisms)
Интерфейс спроектирован так, чтобы минимизировать риск случайной потери данных или некорректного ввода.
Подтверждение деструктивных действий:
Удаление ячейки (как одиночное, так и массовое) вызывает модальный AlertDialog с красной кнопкой «Удалить» и предупреждением, что самокаты вернутся в буфер распределения.
Удаление конкретного самоката из ячейки также требует подтверждения.
Очистка истории (логов) защищена ClearLogDialog.
Валидация ввода в реальном времени:
При создании и редактировании ячейки кнопка «Сохранить/Создать» заблокирована (enabled = description.isNotBlank() && capacity.isNotBlank()), пока поля не заполнены.
Поле ввода ёмкости (Capacity) фильтрует любые символы, кроме цифр: if (it.all { char -> char.isDigit() }).
Защита при распределении (Буфер):
Если в буфере есть отсканированные, но не распределенные самокаты (переменная undistributedCount > 0), появляется предупреждающий баннер.
Обычное нажатие на ячейку в этом режиме не открывает её содержимое, а предлагает добавить самокаты из буфера в эту ячейку через диалог подтверждения, показывая, сколько мест осталось.
Массовое добавление (Bulk Add):
Диалог BulkAddScootersDialog считает количество распознанных строк до нажатия кнопки (показывает «Распознано: N номеров»), чтобы пользователь визуально проверил, правильно ли скопировались данные. Кнопка блокируется при пустом вводе.
Защита навигации: Системная кнопка "Назад" перехватывается (BackHandler(enabled = isSelectionMode)), если включен режим множественного выделения, чтобы пользователь сначала вышел из режима, а не покинул экран случайно.
🧩 4. Ключевые компоненты UI
StorageScreen (Главный экран)
Основной контейнер Scaffold. Содержит:
Умный поиск с подсветкой синтаксиса (ищет по имени, описанию и номерам самокатов).
Скроллируемый ряд фильтров (Все, Есть место, Заполненные, Пустые).
LazyVerticalGrid для рендера ячеек в две колонки.
StorageCellTile (Карточка ячейки)
Высокоинформативный виджет. Что он показывает:
Название и статус (иконка замочка, если заполнена).
Имя и аватар создателя + время создания («2 ч назад»).
Крупный счетчик «занято / всего» с динамическим цветом.
Индикатор (полоса) заполненности.
Микро-бейдж операций за сегодня (стиль терминала).
Smart-подсветка: При поиске, если найден конкретный номер внутри ячейки, он всплывает прямо на карточке зеленым цветом (компонент HighlightedText).
CellDetailsSheet (Детали ячейки - Bottom Sheet)
Шторка, открывающаяся по клику (если буфер пуст).
Метаданные: Дата создания, роль создателя (админ/работник).
Система вкладок (Crossfade Switcher):
Вкладка "Список": Перечень номеров с возможностью точечного удаления (крестик).
Вкладка "Операции": Переключает контент на компонент CellOperationsTerminal.
Кнопки действий: Быстрый экспорт и удаление ячейки.
CellOperationsTerminal (Хакерский лог)
Специальный UI-блок для истории ячейки.
Вид «окна MacOS/Linux» (три кружочка в углу).
Строки появляются с анимацией печатной машинки.
Разные цвета для разных операций (Зеленый = Создание/Добавление, Красный = Удаление, Желтый = Редактирование).
Отображает кто, когда и что сделал (с дельтой изменений +5 или -2).
CellExportSheet (Меню экспорта)
Удобное окно для обмена данными:
Копирование списка в буфер обмена (as is / отсортировано).
Генерация Excel-файла (через StorageExportManager) с вариантами под печать (столбцами) или просто таблицей.
⚙️ 5. Связь с бизнес-логикой
Управление состоянием идет через QrScannerViewModel и AuthManager.
Стейт: uiState.cells, uiState.isLoading, uiState.error, uiState.activityLog.
Жизненный цикл: Используется LifecycleEventObserver для автоматического обновления данных (pulling) при возврате приложения на экран (ON_RESUME).
Ролевая модель: Логика учитывает роль пользователя (authState.isAdmin), открывая доступ к удалению всей истории (кнопка DeleteSweep в логах).

### 📂 `features/inventory/data/repository`

#### 📄 `StorageRepository.kt`
**Назначение:** Основной репозиторий для управления ячейками хранения (Storage Cells) в Firebase Firestore.
- **Функционал:** 
  - Получение списка всех ячеек в реальном времени через `Flow`.
  - Добавление, удаление и редактирование ячеек.
  - Управление содержимым ячеек (добавление/удаление ID объектов).
  - Логирование операций в подколлекцию каждой ячейки.
- **Технологии:** Firebase Firestore (коллекция `storage_cells`).

---

### 📂 `features/inventory/data/export`

#### 📄 `StorageExportManager.kt`
**Назначение:** Логика экспорта данных в формат Excel (.xlsx).
- **Режимы:**
  - `exportCellAsIs`: Компактный список "как есть".
  - `exportCellForPrinting`: Форматирование для печати (столбцы по 50 записей).
  - `exportAllCellsToExcel`: Полный бэкап всех данных склада.

#### 📄 `PalletExportManager.kt` и `PalletLabelGenerator.kt`
**Назначение:** Управление логистическими паллетами и генерация печатных этикеток для них.

---

### 📂 `features/inventory/data/mapper`

#### 📄 `InventoryMappers.kt`
**Назначение:** Маппинг между DTO (Firestore) и доменными моделями. Обеспечивает корректную десериализацию данных, включая временные метки (Timestamp) и списки операций.

---

### 📂 `features/inventory/data/worker`

#### 📄 `InventorySyncWorker.kt`
**Назначение:** Гарантированная отправка локальных изменений в облако при восстановлении связи.
